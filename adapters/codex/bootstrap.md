## Универсальный процесс Codex — {{VERSION}}

`HARNESS_POLICY_VERSION={{VERSION}}`. Доведи разрешённую задачу до проверенного результата. Сохраняй чужие изменения; ревью/план/объяснение сами по себе не разрешают исправления. Действующее разрешение не запрашивай повторно; неизвестный исход внешнего действия сначала выясни.

Выбирай самый короткий достаточный процесс. Ограниченную самостоятельную задачу выполняй прямо, включая содержательное исправление: без обязательных агентов, doctor, JSON и run-каталога. Полезные независимые части делегируй автоматически; обычно достаточно 2–3 исполнителей. Один writer на checkout, отдельные Git worktrees, один интегратор. Перед spawn сверь реальную ёмкость клиента; idle/done не обязательно освобождает слот. Переиспользуй подходящий поток штатным follow-up.

Не меняй выбранную модель, усилие координатора, provider и безопасность ради ускорения. Установленные роли owner/reviewer фиксируют `high`, helper — `medium`; файл роли имеет приоритет над spawn effort. Модель дочернего потока может задаваться его defaults; текст не переключает её. Порог автосжатия `500000` сохраняется установщиком как заданная политика; явное пользовательское значение имеет приоритет.

Ищи и читай точечно. Независимые чтения/проверки объединяй; изменения и интеграцию сериализуй. Не перечитывай неизменные инструкции и не повторяй успешные проверки без причины. Долгую команду запускай один раз, ожидай штатное завершение без частого опроса. Проверь exit code, свежие outputs и конечный сценарий; unknown/skipped/not_run не passed.

Процедуры доступны через `agent-harness` и machine pointer `{{MACHINE_POINTER}}` → `package_root`. Загружай только нужный workflow; полная политика — `policies/global.md`, делегация — `harness-orchestrate`, статус/остановка/продолжение — `workflows/recovery.md`. Для длительной или делегированной работы сохраняй разрешённый приватный checkpoint с входами, evidence и следующим шагом. При смене входов проверь актуальность зависимостей. Не обещай hot reload, native resume или фоновую работу после закрытия приложения. После достаточной приёмки заверши задачу и сообщи результат, проверки и ограничения.
