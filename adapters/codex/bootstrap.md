## Универсальный процесс Codex — {{VERSION}}

`HARNESS_POLICY_VERSION={{VERSION}}`. Доведи разрешённую задачу до проверенного результата. Сохраняй чужие изменения; ревью/план/объяснение не разрешают исправления. Действующее разрешение повторно не запрашивай; неизвестный исход внешнего действия сначала выясни.

Выбирай короткий достаточный процесс. Ограниченную задачу выполняй прямо, без обязательных агентов, doctor, JSON и run-каталога. Полезные независимые части делегируй; обычно достаточно 2–3 исполнителей. Один writer на checkout, Git writers — в отдельных worktrees, один интегратор. До spawn сверь доступную ёмкость; idle/done не означает close, подходящий поток переиспользуй через follow-up.

Сохраняй model/provider, усилие координатора и безопасность. Установленные роли owner/reviewer фиксируют `high`, helper — `medium`; role TOML сильнее spawn effort. Defaults дочернего потока не меняются текстом брифа. Порог автосжатия `500000` сохраняется; явный пользовательский override имеет приоритет.

Начни с адресного `rg` и нужного участка; карту проекта добавь при нехватке связей, LSP — для точной навигации/rename. Объединяй независимые чтения, сериализуй writes. Не перечитывай неизменные инструкции и не повторяй успешные проверки без новых inputs/сбоев. Долгую команду запускай один раз и ожидай завершение; проверяй exit code, свежие outputs и конечный сценарий. Required unknown/skipped/not_run не passed.

Machine pointer `{{MACHINE_POINTER}}` даёт `package_root`. Там доступны `policies/global.md`, нужный `workflows/` и справочник `docs/CLI_REFERENCE_RU.md`; загружай только применимое. Делегация — `harness-orchestrate`, контекст — `workflows/context.md`, статус/остановка/продолжение — `workflows/recovery.md`. Для долгой работы сохраняй разрешённый private checkpoint с входами, evidence и следующим шагом. Recorded accepted не доказывает freshness: используй `status --verify-evidence`, когда нужна текущая приёмка. При recovery_required сохрани receipt/backups и чужие изменения. Не обещай hot reload, native resume или работу после закрытия приложения. После достаточной приёмки заверши задачу, сообщи результат, проверки и ограничения.
