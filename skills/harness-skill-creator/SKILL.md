# Создание скиллов для harness

Установи результат, примеры запросов и разрешённое место сохранения. Различай
source assets пользовательского Git repo, локальные Codex skills и skills,
управляемые платформой. Personal install flow не применяй к исходникам проекта.
Если доступен штатный `$skill-creator`, следуй его применимым инструкциям;
проверь существующие skills, не дублируй процедуру без причины.

Один skill — одна повторяемая процедура. В YAML frontmatter обязательны `name`
(имя папки, lowercase с дефисами, до 64 символов) и короткий `description`:
что делает и когда нужен. Body оставь для необходимых решений/ограничений;
подробности — в связанных `references/`, повторяемые операции — в `scripts/`,
реальные шаблоны — в `assets/`. Не добавляй пустые каталоги, README/changelog
в каждый skill или незавершённые шаблоны. Сохраняй названия/ресурсы существующих
bundled skills: installer блокирует исчезнувший asset и ручную правку.

Действуют текущие полномочия и read-only scope. Не записывай секреты/чужой
контекст и не добавляй подтверждение уже разрешённой работы. Зависимости должны
быть необходимыми; для optional connector опиши рабочий fallback и точный blocker.
Каталог: `{{PACKAGE_ROOT}}/integrations/README.md`. Не меняй implicit/explicit
invocation без запроса; доступную настройку сверяй в целевом клиенте.

Проверь YAML, пути, отсутствие черновых placeholders/противоречий. Новые scripts
реально запусти на изолированных входах. Проверь целевой запрос, похожий посторонний
и missing optional tool; сложную процедуру полезно независимо проверить в общем
бюджете. Структурная валидация не доказывает поведение агента. При оптимизации
поведения используй `{{PACKAGE_ROOT}}/workflows/experiments.md`: фиксированный
verifier, baseline, holdout, bounded trials и keep/discard; это не обязательный
эксперимент перед обычной правкой.

Source skill пакета размещай в `skills/harness-<name>/`. Installer копирует все
ресурсы, а в Markdown подставляет `{{PACKAGE_ROOT}}` и `{{MACHINE_POINTER}}`;
в исполняемом коде эти templates не используй. References установленного skill
должны вести в package через template root, не случайный относительный cwd.
Проверь rendered paths в изолированном home, сохраняя ожидаемые source templates.
Для другого skill используй назначенный location и штатный validator.
Обновление/rollback: `{{PACKAGE_ROOT}}/SETUP_RU.md`; глобальную установку для
проверки source asset не запускай.
