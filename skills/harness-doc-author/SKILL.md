# Технический автор

`technical_writing_level: 50` — внутренняя шкала качества 0–100. Она задаёт
умеренно строгий инженерный стиль и не означает соответствие ASD-STE100.

Определи аудиторию, тип документа, разрешённые файлы и ожидаемый сценарий.
Для обычного изменения кода без документального результата этот skill не нужен.
Изменение документа не разрешает публикацию или исправление product code.

1. Сопоставь требования с актуальными исходниками, схемами и revision.
   Команды проверь через действующий `--help` и безопасный изолированный пример.
   Запиши, что реально проверено; наличие команды не доказывает весь сценарий.
2. Выбери нужные разделы: назначение, prerequisites, quick start, установка,
   конфигурация, tutorial, справочник, troubleshooting, безопасность.
   Используй формат существующего проекта; не добавляй пустые разделы.
3. Пиши короткими однозначными предложениями. Один шаг — одно действие.
   Объясняй условие и последствие, сохраняй термины, раскрывай сокращения.
   WARNING обозначает риск для людей; CAUTION — риск для данных/результата;
   NOTE — полезное пояснение. Не копируй защищённый текст стандартов.
4. Для примера укажи cwd, входы, команду, ожидаемый результат и ограничения.
   Сохраняй реальную семантику Windows/POSIX. Не обещай неподдерживаемые flags,
   API, перезагрузку старой сессии или выполнение после закрытия приложения.
5. Диаграммы строй по реальным вызовам/состояниям. Проверь связанные узлы,
   внутренние ссылки, версии, доступность описания без цвета и рендеринг.
   Если renderer отсутствует, сохрани source и статус `not_run`; не называй
   схему визуально проверенной. Для обязательного render это остаётся blocker.
6. Передай reviewer единый packet: revision, изменённые docs, source mapping,
   выполненные примеры, diagrams и оставшиеся unknowns. Исправления объединяй
   в одну содержательную волну, затем повтори затронутые проверки.

Подробности по задаче загружай адресно:
`{{PACKAGE_ROOT}}/workflows/document.md`,
`{{PACKAGE_ROOT}}/docs/CLI_REFERENCE_RU.md`,
`{{PACKAGE_ROOT}}/docs/EXECUTION_SUPERVISOR_RU.md`.
Для нового skill используй `{{PACKAGE_ROOT}}/skills/harness-skill-creator/SKILL.md`.
Отсутствующий необязательный connector не мешает локальной документации:
используй разрешённые исходники и явно обозначь недоступную внешнюю проверку.
