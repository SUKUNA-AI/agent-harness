## Исправления

| Область | Ошибка и новое поведение |
|---|---|
| Свежесть test report | Старый успешный JUnit/JSON и no-op команда больше не дают принятие. Наблюдаются file identity/size/timestamps до и после запуска; реальная перезапись с идентичными байтами допускается. |
| Финализация check | Неверная вложенная структура JSON, copy/snapshot/log-capture errors дают failed evidence. Запись процесса закрывается даже при невозможности записать result; такая ошибка не объявляется успешным сохранением. |
| Recovery dependencies | `resume` использует общий read-only accepted-evidence validator, проверяет receipts, исходники, artifacts и цепочку принятых зависимостей. Изменившаяся dependency блокирует прежнее принятие. |
| Бюджеты | Обычная новая attempt не может увеличить max_attempts, продлить или удалить deadline. Недопустимые типы budget отклоняются. |
| Native capacity | Явные `root_counts=false` для child-only cap и `true` для общего cap. Root остаётся в inventory и участвует в проверке writers. Допустим `target_owners=1`. |
| Git checkout | Пустой marker `.git` не объединяет чужие каталоги в один checkout. Проверяются настоящие metadata, gitdir/commondir, linked worktrees. |
| Установка | Финальные manifest/active writes входят в транзакцию. Сбой компенсирует её изменения, не затрагивая concurrent user edits; неполное восстановление сообщает ошибку. |
| Installation integrity | Без active manifest нет ложного unchanged/structural_verified. Проверяются сохранённые backup/installed copies и ownership hashes. |
| TOML rollback | Каждый обратный agents/root/alias/table edit сверяется по семантике TOML; regex не может незаметно изменить пример внутри multiline-инструкции. Учтены LF/CRLF и dotted config без завершающего newline, в том числе прежние manifests. Неоднозначный случай блокируется до записи. |
| Legacy cap | `max_threads` обратимо мигрирует в единственный `max_concurrent_threads_per_session`. Обычная установка сохраняет более строгий предел; явный CLI override применяется отдельно. |
| Doctor | Разрешённые model/provider/effort/context/tool settings показываются с файлами-источниками, включая profile files и roles. Произвольные инструкции и provider credentials не включаются. Effective runtime остаётся неизвестным до client probe. |
| CI fixtures | Cancellation синхронизируется по действительному запуску; отмена до spawn проверяется отдельно. Legacy uninstall fixture использует фактические LF/CRLF строки metadata. |

## Ускорение процесса

Самостоятельное ограниченное исправление допускает прямой путь без обязательных
агентов, doctor, JSON и run/gate. Формальный lifecycle сохраняется для длительной,
делегированной и требующей состояния работы. Делегация используется для полезных
независимых частей. Native inventory и пределы клиента по-прежнему проверяются.

Bootstrap сокращён с **6759 до 3617 байт UTF-8** относительно базы аудита: примерно
**46,5%**. Это размер конкретного файла, не число токенов и не измерение задержки
LLM. Полная политика и процедуры читаются по необходимости; неизменные правила
повторно не загружаются. Независимые чтения объединяются, после исправлений
повторяются затронутые проверки и обязательные integration gates.

`model_auto_compact_token_limit = 500000` оставлен. Явное пользовательское значение
по-прежнему имеет приоритет. Параметр задаёт порог сжатия истории, но не увеличивает
окно модели; клиент/модель могут ограничить контекст раньше. Экономия токенов и
ускорение в секундах в этой проверке не измерялись.

Сценарное чтение инструкций проверило самостоятельный fix, независимые lanes,
recovery и неизвестный исход внешнего действия. Оставшиеся безусловные требования
run/gate и делегации по одному размеру задачи устранены. Это проверка согласованности
инструкций, не модельный behavioral benchmark.

Окончательный hosted CI проверяется в [Actions](https://github.com/SUKUNA-AI/agent-harness/actions)
по точному опубликованному commit: Windows/Ubuntu, Python 3.11/3.13, suite/release
audit и настоящий stdio MCP smoke с pinned SDK. Локальный результат его не заменяет.
Проверка применения patch, совпадения Git tree и статуса опубликованного commit
фиксируется отдельно в `delivery.json` поставочного ZIP.

Codex CLI и pinned MCP SDK в этой локальной среде отсутствуют. Новый native
parser/prompt-input, фактический model/effort текущего пользовательского профиля
и замер latency LLM здесь не запускались. Исторические native проверки из
[отчёта 1.1.0](RELEASE_REVIEW.md) не служат квалификацией нового выпуска.

Для свежести отчётов нужны различимые file metadata. Если файловая система не
отличает идентичную перезапись, используйте новый output path на каждый check;
неизменный прежний файл отвергается. Harness кооперативный, не OS sandbox для
враждебного кода. Изменение правил не обещает hot reload открытого чата: обновите
установку через dry-run/apply/verify и откройте новую сессию Codex.
